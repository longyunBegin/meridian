# 认知发动机 · 置信度更新公式（红区评审方案）

> 状态：书面方案，未实现。需评审通过后方可实施。
> 涉及红区：`calibration()/trustFor()` 公式体系。

## 用户定义的公式

### 支持更新（贝叶斯风格，边际递减）
```
new = old + (1 - old) × strength × α
```

### 反驳更新（波普尔式证伪，力度更大）
```
new = old - old × strength × β
```

其中 α < β（反驳比支持更有力）。

### 边际递减机制
- 第 1 条支持证据提升大，第 10 条提升小
- 同一信息源的第 2 条证据，权重是第一条的 0.5 倍左右
- 避免一条新闻被反复引用导致置信度虚高

## 与现有系统的关系

### 现有 `calibration()` / `trustFor()`
- 用途：来源可信度校准（source quality → trust score）
- 输入：来源历史表现、证据类型
- 输出：0-1 之间的信任度

### 新公式的定位
- 用途：命题置信度更新（proposition confidence update）
- 输入：当前置信度、证据强度、证据类型权重、信息源去重系数
- 输出：更新后的置信度

**关键区别**：`trustFor()` 算的是"这个来源有多可靠"，新公式算的是"这个命题有多可信"。前者是输入，后者是输出。

### 建议的集成方式
1. `trustFor(source)` → 得出证据的 `strength`（0-1）
2. 新公式 → 用 `strength` 更新命题的 `confidence`
3. 两层分离，互不干扰

## 状态迁移阈值（用户定义）

| 条件 | 状态 |
|------|------|
| 置信度 > 0.75 | 稳定 |
| 置信度 < 0.5 或出现强反驳 | 受质疑 |
| 结算日到期 | 待结算 |

## 待评审问题

1. **α/β 具体值**：用户未指定。建议初始值 α=0.3, β=0.5，通过实际数据校准。
2. **强度计算**：`strength` 由证据类型（硬事实=1.0，软事实=0.7×来源可信度）× 信息源去重系数 得出。需要明确公式。
3. **与现有置信度的兼容**：现有命题的 `confidence` 字段是 0-100 整数，新公式用 0-1 小数。需要统一。
4. **事件记录**：每次置信度更新应追加 `confidence.updated` 事件（新事件类型），记录 old→new、原因、证据ID。
